# Public-data benchmark: CORD-v2

End-to-end benchmark for `dsh-invoice-ledger` using the public CORD-v2
receipt dataset.

- Data: <https://huggingface.co/datasets/naver-clova-ix/cord-v2>
  (test split mirror used: <https://huggingface.co/datasets/Heliosoph/CORD>)
- License: **CC BY 4.0** — NAVER Clova / CORD authors
- The image/JSONL files are downloaded by `fetch.mjs` and are **not**
  committed.

## What is real and what is not

CORD contains gold receipt annotations (`gt_parse`) with menu lines, subtotal,
tax and total. It has **no invoice code/number, issue date, buyer, seller,
tax rate, reimbursement form or red-letter marker**. The adapter maps only
fields that exist and marks the rest as not provided; those rules are excluded
from P/R rather than being scored against fabricated values.

The scored rules are the money identity (`INV-003`), amount range (`INV-023`),
and the shipped file-link checks (`INV-007`, `INV-024`) using the real public
JPEGs. The missing-original and zero/negative-total cases are **injected
defects** derived from real receipts.

## Run

```bash
node bench/public-cord/fetch.mjs --from /tmp/public-data/cord
node bench/public-cord/evaluate.mjs --limit 20
```

`RESULTS.md` and `summary.json` are generated by the evaluator. See
`RESULTS.md` for the P/R table, excluded rules and the honest limits
(Indonesian receipts, no OCR evaluation, small selected subset).
